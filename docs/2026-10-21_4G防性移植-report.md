# 4G 盾斧防性移植到 Moveset

2026-10-21。适用 MHGU v1.4.0，参照 MH4G v1.2 原版。已实现、编译并完成离线回归；未进行游戏内战斗测试。独立的“第七种 4G 风格”不在本次范围内。

## 行为与配置

`[moveset] guard_performance = true` 默认开启。菜单显示 **4G guard performance (GP / red shield)**，可保存到当前用户存档根目录的同一份 INI，重启生效。旧 INI 缺少此键时也使用默认 true。

开启后，白盾／红盾的 GP 在 GU 防御性能技能计算完后额外减去本次攻击防御威力 10，最低为 1。红盾不再执行 GU 原有固定减 10，改为使用 4G 的 40/50 硬直阈值。以下 P 为无防性技能的原始攻击防御威力，中硬直位于小、大两档之间。

| 状态 | 小硬直 | 大硬直 |
|---|---|---|
| 白盾普通防御 | P < 15 | P >= 40 |
| 白盾 GP | P < 25 | P >= 50 |
| 红盾普通防御 | P < 40 | P >= 50 |
| 红盾 GP | P < 50 | P >= 60 |

例如 P=55 的红盾 GP：先减 10 得到 45，再按红盾 40/50 分类为中硬直。

六种原版风格共用上述规则。4G 没有黄盾／蓝盾，本次保留它们的 GU 原判定：黄盾减 10；蓝盾仅在原特殊反应位成立时减 10，不额外叠加新 GP 减值。J 防的特殊受击流程未被替换。

## 实现与原版证据

| 证据 | 原版位置 | 已核对的作用 |
|---|---|---|
| E-001 | 4G `0x00B2804C` | 防性技能后检查独立 GP 位 `0x2000`，再减 10，最低 1 |
| E-002 | 4G `0x00B0E618..0x00B0E65C` | 白盾 15/40，红盾 40/50，返回实际硬直档位 |
| E-003 | GU `main+0x002F4A2C` | 读取原始防御威力，处理技能，再调用武器虚函数 `+0x878` |
| E-004 | GU `main+0x011DFB0C` | 盾斧的黄／红／蓝盾原减值回调 |
| E-005 | GU `main+0x002F0800` | 包含盾斧的 15/40 分类分支，汇合点为 `main+0x002F0828` |

原版指令快照在 [guard-fixtures.json](../tests/guard-fixtures.json)。验证脚本可以再与本机原版 GU main、4G ELF 逐字节核对，避免把 asset 修改后的资源当作原版参照。

新增 [guard.rs](../Moveset-to-4G/src/guard.rs) 只收集两处 8 字节绝对跳转：

- `main+0x011DFB0C` 原 `E92D4830 / E1A05000`，跳到 NRO 的威力修正函数；调用者仍是 GU 共用技能计算函数。
- `main+0x002F0800` 原 `E3A08002 / E3500027`，跳到 NRO 的分类桥接。仅武器编号 14、盾状态 2 使用新阈值，直接返回原分类汇合点；其它情况补回原两条指令。

关闭开关时两处均不安装。补丁沿用项目事务安装器，一次核对并写入，任何原指令或缓存刷新失败都回滚整组。不占用 main 的代码洞。

## GP 判断与现有后退补丁的关系

同时满足以下条件才获得新 GP 减值：

1. 玩家 `+0x333C` 为 1，即原版 GP 窗口阶段。
2. 玩家 `+0x2510` 的通用防御有效位 `0x10` 成立。
3. 当前实际动画为 `5014..5016、5105..5107、5109、5112..5113、5131、5146、7051、7151`。

动画列表来自共享 GP 函数 `main+0x011DDDF0` 的调用者和 `011D7AF0 / 011D9F9C / 011DC43C / 011DF014` 内联窗口。各动作初始化清零阶段，进入／退出窗口写入 1／2。动画索引 `+0x4B4` 经虚函数 `+0xC0` 转换，等价于 `sub_6053A058`；直接把索引当成实际动画编号会判断错误。

这些字段读法归入 `game-api/src/player.rs` 的玩家对象。GP 防性不读取特殊反应位 `+0x3340 & 0x20`；现有 `gp_recoil` 会为部分风格取消这个位，两个开关因此可以独立工作。普通防御动画及动作切换后的遗留阶段不会获得新 GP 减值。

## 验证结果

- 25,717 组实际编译后的 ARM 威力计算：覆盖原始威力 0..255、正负防性技能、两个加载基址、全部 8,192 个候选动画编号、阶段／有效位失效及两种特殊反应位。白盾／红盾与 4G 原函数的计算结果一致。
- 34,560 组分类：白盾／红盾与 4G 原指令返回档位一致；黄／蓝盾和其它武器与 GU 原指令一致，分类桥接保留其余寄存器、栈和 VFP。
- 1,024 种配置组合及 70 组事务回滚；Forge 菜单编辑／保存、默认值、旧 INI 缺项及启动快照通过。
- 完整 `test.sh` 通过，包含原有派生、GP 后退、表现、超模、HDP、SAED 时序／位置回归。
- NRO 的 ARM32 ABI、ELF 段、MOD0、BSS、可写重定位、导出回调、当前 Forge／GU 强符号导入全部通过。没有 TEXTREL。

复现命令：

```bash
bash "test.sh" "/path/to/MHGU-dump" "/path/to/4G-ExeFS.elf" "/path/to/Forge-subSDK"
```

产物为 `dist/cb_moveset_to_4g.nro`，77,824 字节，SHA-256 为 `0cb718bb63b747a53a124a1607dfb81ece39d4125a77d99277adf0cb42c5828c`。测试是代码执行与装载约束验证，实际战斗表现仍须重启游戏验证。

## 设计取舍与完成核查

防性计算集中在一个功能模块，对象偏移集中在玩家接口；复用现有配置、菜单和补丁事务。使用原 GP 阶段及实际动画，不增加一套每玩家 GP 状态、不挂多处窗口钩子，也不增加每帧回调或分配对象。这对应职责分离、复用现有代码和仅实现当前需求。

| Finding | 类型 | 状态 | 证据 | 结论 |
|---|---|---|---|---|
| F-001 | n/a_re | validated | E-001,E-003,E-004 | 新威力修正保留原技能顺序，白盾／红盾 GP 与 4G 一致 |
| F-002 | n/a_re | validated | E-002,E-005 | 红盾分类改为 40/50，没有重复叠加 GU 红盾减值 |
| F-003 | n/a_re | validated | E-003,E-004,E-005 | 黄／蓝盾与其它武器保持原版结果，后退补丁不阻断新 GP 减值 |

调用链：GU 技能计算 → NRO 盾斧修正 → NRO 红盾分类／GU 原分类 → GU 原防御受击处理。剩余验证仅为用户在游戏内测试不同招式与攻击威力，没有未完成的代码接入。
