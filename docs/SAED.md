# Moveset 中的 SAED 功能

已整合进 `cb_moveset_to_4g.nro`；INI 只保留 `[saed] enabled` 和 `effect_gear`，默认启用、档位 2，见 [配置说明](Configuration.md)。第三 hit、瓶伤、逐瓶时序／轨迹／贴地和特效档位整组启停。其余数值固定为本文设置，SH 可以使用游戏原版。第三下地面斧攻击使用运行时追加的 HDP `0x50`，动作值 100。

| 修改 | main 位置 | 备注 |
|---|---|---|
| 超解第三次命中（3 hit） | 011DADD4～011DADE8、011DB18C、011DBDA0～011DBDB4、011DBE50 | 地面改用新增 0x50；空中仍为 0x23；移除 011DB014 的替换补丁 |
| 超解瓶伤 | 0048906C～00489078 | 4 处直接值原样保留；有瓶爆参数时 s18 固定为 1.35，取代按剩余瓶数增加的系数 |
| 超解瓶爆特效档位 | 011DE830、011DE838、011DE83C | 非零瓶数统一采用 r9 指定的档位，当前为 2，供核对特效；保留原属性分支、真实瓶数和瓶爆次数，零瓶仍返回 |
| 瓶爆初始化／更新／销毁 | 00488C0C、00488DE4、00488BDC | 按瓶型选择 NRO 时间表，支持 1～10 瓶，逐爆重算世界坐标与地面高度 |
| HDP 加载后扩容 | 00270C18 | 80 条扩为 81 条，原条目保持加载文件的内容，末尾追加 0x50 |

两处 BL 仍调用原版 HDP 创建函数 `main+0x002B7240`：`011DADE4 EBC37115` 和 `011DBDB0 EBC36D22`。1.35 字面量仍位于 `00489078`，由 `0048906C` 的 PC 相对 VFP 加载读取，随后跳过字面量。

特效档位直接修改 INI `[saed] effect_gear`（1..4），保存后重启，无需重编。`enabled=false` 时整组 21 处改值、瓶爆钩子和 0x50 追加均不安装，特效选档也关闭。该数值仍是 r9 档位，后面的榴弹／属性分支再转换成资源类型，并非 effectId 或真实瓶数。

## 固定瓶爆时间与位置

下面是 [schedule.rs](../Moveset-to-4G/src/saed/schedule.rs) 的固定源码参数，不再提供 INI 调整。所有时间都累加 shell 的 `mDeltaTime`（`+0x1C`），使用与原 GU SH 计时相同的单位。

- `impact_interval = 9`：榴弹两爆之间的间隔，与 4G 原表一致。旧 SH 的完整 21 为 6+6+9，不作为逐爆间隔。
- `impact_first_delay = 0`：4G 普通地面超解的榴弹首爆没有额外等待，在 GU 进程首个有效更新创建特效和攻击判定。
- `element_first_delay = 46`：4G 普通地面超解的强属性首爆在进入瓶爆表前等待 46。
- `impact_first_forward = 270`、`element_first_forward = 300`：第一爆的前进距离，后续位移统一加在这个偏移上。
- `end_delay = 9`：最后一爆之后的收尾时间，随后通过原 shell 停止函数回收。

下表时间相对实际第一爆；距离相对首爆当帧玩家坐标，沿进程初始化时的水平朝向旋转。首爆时锁定这份坐标，之后人物移动不会改变后续轨迹。榴弹第一爆在玩家前方 270，随后是 370、470……，相对第一爆的距离为 0、100、200……。暂停更新（delta=0）不提前触发首爆。

首爆倒计时来自 4G `AED_hit`（`0xC60644`），普通地面超解 `process+660=2` 时，榴弹类型 5 为 0，强属性类型 4 为 46；瓶爆表首项时间 0 不代表两种瓶型都没有首爆延迟。原版进程在构造时记录人物坐标；本版采用首爆当帧坐标，是为适配 GU 等待期间人物前移而做的调整，距离数值沿用 4G。

| 强属性瓶序号 | 累计时间 | 横向距离 | 前方距离 |
|---|---:|---:|---:|
| 1 | 0 | 0 | 300 |
| 2 | 18 | 80 | 420 |
| 3 | 20 | -80 | 420 |
| 4 | 38 | -120 | 540 |
| 5 | 40 | 120 | 540 |
| 6 | 42 | 0 | 540 |
| 7 | 58 | -160 | 660 |
| 8 | 60 | 160 | 660 |
| 9 | 62 | -160/3 | 660 |
| 10 | 64 | 160/3 | 660 |

前六项来自 4G 初始化后的原表，加上创建进程时的前移 200。后三组分别有 2、3、4 个点；第七至十项为 GU 十瓶外推的第四组，并非 4G 原有数据。瓶数不足一整组时依次使用表中已有点，每次更新至多爆一瓶。

左右偏移是相对出生时中心线的绝对值，不是每一爆继续累计的移动量。2026-10-03 重新执行 4G 原旋转／平移 ARM 指令，256 个朝向共 1536 个前六爆坐标与 NRO 计算一致，最大误差 0.000122。第二组的两点间距为 160，第三组最左与最右间距为 240。这验证的是爆点坐标；尚未取得游戏画面中粒子自身局部偏移的运行证据，因此保留这些坐标，并按用户要求将资源档位改为 2 供测试。

## 逐爆贴地及原版调用

[phial.rs](../Moveset-to-4G/src/saed/phial.rs) 在原 init 成功后记录参数对象 `+0x11` 的瓶数和 `+0x08` 的资源子类型。子类型 0～3 为榴弹，其余 4～27 为强属性，属性伤害的原初始化仍执行。

每次到达时间表中的目标：

1. 第一爆重新读取人物 X/Y/Z 并锁定；用这一基准和初始化的 yaw 算新的 X/Z，后续只使用锁定位置。
2. 以先前高度为基准，按 4G 的 `(上方+300、下方-2000)`、`(上方+2000、下方+300)` 两组参数调用 GU 地面查询 `main+0x00181440`。命中则取返回的地面 Y，均未命中则保留先前高度。
3. 更新 shell `+0x40/+0x44/+0x48` 及 `+0x1000` 镜像位置。
4. 复用 GU 特效选择／创建函数，保留资源子类型决定的特效和尺寸。
5. 参数对象 `+0x11` 减一，调用未改动的瓶伤函数 `main+0x00488FC0`。四条 1.35 补丁保持原值。

shell 的原后处理继续更新朝向矩阵和攻击对象。每次提交攻击会走原 `Read_HDFfile` 及其命中序号更新。父对象离场时保留原回收调用；NRO 读取 `shell+0x0C` 的原生存活标志后停止自身序列。动作切换不会额外中断已经生成的瓶爆。

`game-api/src/abi.rs` 用两段 ARM 适配函数接收游戏的 `s0` 浮点参数／返回值。它们保留 ABI 要求的寄存器和 8 字节栈对齐，防止把返回的整数寄存器误当高度。`SaedShell` 和 `GroundProbe` 封装原生调用，4G 轨迹与两次贴地探测规则仍在 `saed/` 中。

## 运行时追加 0x50

[hitdata/mod.rs](../Moveset-to-4G/src/hitdata/mod.rs) 挂在 `rHitDataPlayer::load` 成功返回后，只处理盾斧 `pl_we14_hitdata`，与 Hitdata 复制共用同一次加载回调。

- 文件头 16 字节，每条 56 字节；原版为 80 条／4496 字节，扩容后为 81 条／4552 字节。
- SAED 自身把原来的全部 80 条数据原样复制。`[hitdata] enabled=true` 时，`0x00～0x4E` 再改成内嵌 asset，`0x4F` 恢复原版完整记录（延迟 106、持续 6、动作值 55）；新增的 `0x50` 保留。两个开关互不控制。
- `hitdata/records.rs` 的 `NEW_50` 内置当时 asset `0x4F` 的完整 56 字节，固定延迟 0、持续 8、动作值 100；不会从当前加载文件的 0x4F 取值。以后调整新增第三下数据，修改此常量并重新编译。
- 通过游戏 HDP 同一分配器分配新缓冲，改 `resource+0x64` 的数据指针和 `+0x68` 的条目指针，然后用该分配器释放旧缓冲。原版 unload 仍负责释放新缓冲。

原来 `011DB014 E3A0201A` 已从安装表移除；地面调用 `011DADDC E3A02050`。空中 `011DBDA8 E3A02023`、两个创建 HDP 的 BL 及其余第三下补丁保留。

本版不修改本地 asset、SH 或 HDP 文件，也不再使用 `00488F5C/00488F74` 的旧瓶爆桥接。函数入口通过 Forge 挂钩进入 NRO；原 main 的 `013F1EEC～013F1F54` 不写入。部署后重启游戏，并关闭旧版对应金手指。

## 验证结果

4G ARM 启动初始化表及六个首爆倒计时分支复现、1536 组原指令扇形坐标、100 组 1～10 瓶时序、720 组位置旋转、原版／asset 两份 HDP 扩容、编译后浮点调用 ABI、21 处原值及四个挂钩前导指令核对均通过。另执行实际 phial.rs，确认两种瓶型共 20 个爆点使用首爆当帧基准且后续不随人物移动。安装器的 SAED 缓存失败恢复覆盖 42 组。

本次完成的是离线代码、二进制和算法验证；斜坡／矮墙贴地、连续命中与十瓶特效仍需实际战斗测试。完整依据和复现命令见 [分析报告](2026-10-03_逆向-SAED瓶爆与HDP扩容-report.md)。
