## SRQ / PTS 资源修改

实现位于 `Presentation-to-4G/src/resource.rs`，钩子位于 `src/hooks.rs`。只处理盾斧 common SRQ 和 `sound/pts/pl/w14_000`，每次加载对应资源时应用修改，不做逐帧扫描。

| 资源 | 应用时机 | 修改内容 |
|---|---|---|
| `snd_wp_gaxe_com.srq` | SRQR 原始数据读入后、绑定音库前 | request `0x4A` 音量两个字段 `-3.9 → -1.9`，`+0x34` 重播间隔 `600 → 0`；request `0x54` 整条记录使用当前 asset，包括播放操作、cue `0x4A`、延迟和音库索引 |
| `w14_000.4541367C`（PTS） | XFS 成功解析为条目对象后 | 下表列出的 13 条伴生音效修改 |

| 特效组 | effectId | 事件 | 当前 asset / NRO 的处理 |
|---|---|---|---|
| SEQUENCE | `0x226` | 创建 / 结束 | request `0x4A` 创建、`0x56` 结束的 `mEventType` 均置 0，关闭这两次调用 |
| SEQUENCE | `0x258 / 0x259 / 0x262 / 0x263` | 创建 | request `0x48 → 0x47` |
| UNIQUE | `0x1F4` | 结束 | request `0x54 → 0`，保留 `mEventType=3` |
| UNIQUE | `0x258 / 0x259 / 0x25D / 0x25E / 0x262 / 0x263` | 创建 | request `0x48 → 0x47` |

`0x4A` 的 `+0x34` 是重播间隔；启播延迟为 `+0x30`，保持原版 0。`+0x14/+0x15` 为两个 u8，分别是优先级／替换方式，当前 110／1；`+0x12` 是分组第三项，不是淡出时间。`0x54` 必须在原函数绑定音库前修改，才能让它的音库索引正常转换为资源引用。PTS 按对象字段 `+0xC`（request）和 `+0xE`（事件）修改，不把文件偏移当成内存偏移。完整当前字段见 [五个插件清单](Plugins.md)。

SRQ 参数快照和 PTS 固定规则直接保存在 `resource.rs`，构建和运行都不打开这两份 asset 文件；调整规则后重新编译。已修改的资源也可继续使用，重复应用的结果一致；`0x1F5` 的 request `0x52`、SEQUENCE `0x22B` 的 `0x4A / 0x56` 保持原值。

这次只替代这两份 SRQ / PTS 的修改；其它 PSL、PEL、动作值、瓶爆间隔和音库资源仍按原配置部署。原始加载函数已验证资源有效后才访问缓冲区／条目对象，沿用它的指针有效前提。

共享资源在顶层 `assets/`，文件内容未改动。你已将参考改版移动到 `weapon-nro`、`sound-nro`，NRO 不依赖这些目录。详细字段和复现验证见 [SRQ / PTS 分析报告](2026-10-02_逆向-Presentation音效资源-report.md)。

## 盾突闪电

配置在 `Presentation-to-4G/src/effect.rs` 的 `on_shield_thrust_start`：榴弹瓶 `0x258`、强属性瓶 `0x259`，持续 `30.0` 帧。使用与大解相同的盾牌附加和持续帧实现。用户反馈加入 request 0x47 后游戏持续闪退，已撤除盾突新增音效调用和音序对象读取；粒子创建不自动提交 PTS 伴生音效。

钩子位于盾突动作入口 `main+0x011DB280`。调用原函数前记住 `actionState==0`，原函数初始化动画后读取 `player+0x3344`：2 为红盾，就在盾牌上创建一次闪电。原函数在起手分支推进 actionState，后续更新不会重复创建。空挥和命中都播放，没有瓶数、狩猎风格、actionID、命中判定或瓶爆返回值条件。

盾状态字段来自原生虚函数 `+0x85C`（`sub_602B6568`），该函数直接返回 `player+0x3344` 的 u32。状态 0／1／2／3 分别为未强化／黄盾／红盾／蓝盾。本次只按用户指定的红盾播放。

旧的 `011DB498` 调用点桥接、等待返回值和尝试标记已撤去；共用 `CreateShell02` 和盾突内部调用点都保持原版。入口前导两条为 `push {r4,r5,r6,lr}`、`sub sp,sp,#8`，不含 PC 相对指令，使用 Forge 函数入口钩子。

验证：576 组实际 NRO 入口指令检查覆盖六个 variant、四个 actionState、四个盾状态、三个原返回值及两个加载基址，确认原函数先初始化、仅起手红盾创建闪电，入口不访问音序对象或调用 SE，返回值和寄存器／栈保留。另执行实际模块及统一瓶型选择函数的 16 组检查，确认榴弹 0x258／强属性 0x259、持续 30。盾牌和 PEL 沿用原动作的有效指针前提；游戏内表现仍待测试。
