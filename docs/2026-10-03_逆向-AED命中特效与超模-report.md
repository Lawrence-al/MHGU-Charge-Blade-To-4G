# AED 命中特效与 Overpowered 实现报告

本次已实现超模 NRO 和五个产物的 `cb_` 前缀；命中特效部分只分析，不加入新钩子或修改资源。五个插件的现行数值见 [Plugins.md](Plugins.md)。

## 结论

4G 普通大解命中后调用的 `AED_hit(0x00C60644)` 是瓶爆进程初始化函数。它为类型 2、3 创建 `effect\efl\wp\gaxe\gaxe_002`，创建成功后在进程的命中世界坐标播放 bank 5、request `0x4B`。这条路径和动作第 66 帧的 `0x4B` 是两个调用来源。

GU 原生大解瓶爆路径已保存怪物对象、命中部位和世界坐标，所以可以在真实命中位置创建指定粒子，不必把 hitdata 标成狩技。要得到相同的 4G 外观，必须转换对应 EFL 及依赖资源；单改 effectId 或把 4G EFL 改名放进 GU 不能完成资源转换。

普通大解的单独砸地尘土，本次尚未从动作／通用碰撞／粒子层中分离并确认具体资源和触发点。已确认的 `gaxe_104` 是该函数 variant 2 的**超解**地面效果，不能把它当作 variant 1 的普通大解砸地效果。下面明确区分已验证结果和后续实现方法。

## Finding

**F-01（E-01～E-05）：命中 `0x4B` 与动作 `0x4B` 分开。** 普通大解先创建斧攻击判定；真实怪物接触后，由 `sub_CA875C` 创建类型 2／3 的瓶爆进程，初始化阶段创建 `gaxe_002`，再从命中坐标播放 `0x4B`。另外 SAED_action variant 1 无论有没有打到怪物，都能在第 66 帧提交附加在武器索引 12 的 `0x4B`。因此不能拿音效是否出现当成“砸中特效已命中”的判断。

**F-02（E-06、E-07）：槽号、粒子路径与砸地路径必须分别追。** Flow `0x2B` 不是 `gaxe_043`，而是解析到 `gaxe_005` 的起手效果。超解砸地 `gaxe_104` 也不是普通大解的证据。现有两段主要函数足够确认普通大解瓶爆命中特效，但还不能独立确定普通大解尘土来自起手 EFL 的延迟粒子层、动画事件还是通用武器地面碰撞。这里的限制是**当前静态证据未完成这部分定位**，不是已证明普通大解尘土无法实现。

**F-03（E-08～E-10）：GU 能直接使用实际命中部位坐标。** 不应按人物前方固定偏移伪造怪物命中点。原大解附加瓶爆已经把目标和部位传给进程，最小的实现可在大解自身的创建路径上，把所需的自定义粒子加入该进程，复用它的定位。若要在无瓶大解等情况下也播放，可从攻击碰撞分发读真正的接触点，而不依赖瓶爆进程。

**F-04（E-10 及模板／asset 对比）：当前修改是 HunterArtFlag。** 你描述的“改 1 后有狩技命中特效”，对应当前 asset 的 record `+0x0E`，模板名称为 `HunterArtFlag`。`HunterArtGen` 在 `+0x26`，控制的是狩技积蓄相关数据，当前没有改。原代码将 flag 作为攻击标记写到怪物参数；它没有存储你要播放的粒子 ID。该标记之后选择狩技命中粒子的具体消费函数尚未确认，所以这里不把该特效的确切 ID 作为已知结论。

**F-05（E-11）：4G 外观需要转换资源。** EFL 版本与依赖不同，GU 的原 loader 会直接拒绝 4G 的版本字并返回加载失败。需要按 GU 格式重建发射器层、时间、位置／旋转／尺寸／颜色曲线、混合和材质引用，并转换它所需的纹理／模型。仅把 4G 文件放到一个新路径，或让 NRO 传一个新的 ID，GU 并不会自动完成这种转换；只改头部版本也没有转换后面的结构和依赖。

**F-06（E-12、E-13）：超模只需跳过记录 0。** 不必更换六份风格文件，也不用删除整个表、复制一张无弹刀表或重排下标。查询桥接在链 `0x7DC`、盾斧、序号 0 时返回失败，原循环继续查询序号 1。原后续窗口及 Moveset J 防桥接都保留。

## Path：现有链与实现建议

P-01（已确认，E-01～E-05 → F-01）：`SAED_action variant=1` → 斧 HDP `0x15` 命中 → `sub_CA875C` 读取目标／部位／世界点 → `Create_SAEDphailthread` 类型 2／3 → `AED_hit` → `gaxe_002` → 命中位置 request `0x4B`。

P-02（可实施方法，E-08～E-11 → F-03、F-05）：把 `gaxe_002` 和依赖转换成 GU 可读资源 → 给 GU 注册独立特效引用 → 在大解自身创建瓶爆进程的调用路径提交该特效 → 使用原参数中的怪物、部位和接触点。让粒子直接附加到该怪物部位，或复用已经处理部位变换的瓶爆进程。不要给所有调用 CreateShell02 的动作无条件加特效；盾突等其它调用方应保留原行为。

P-03（无瓶也要命中粒子时，E-10 → F-03）：在 `main+0x00170968` 的碰撞分发原处理之后，用攻击所属玩家、当前 AED 动作／HDP 和原处理确认的命中结果筛选 → 读参数中的世界接触点／部位 → 同一次攻击只创建一次，复用类似 4G `player+44256` 的一次命中标记。不能拿 `MhHitAtk+5` 的 active 值代替实际命中结果；GU 接受的碰撞结果在 `+6`，应区分怪物命中与弹刀等结果。

P-04（砸地实现方法，E-05、E-07 → F-02）：普通大解砸地触发使用动作事件，与怪物命中分开；以斧头落点查询实际地面，在返回的世界位置创建地面粒子，父对象不使用盾牌。GU 已有 `00181440` 地面查询，可沿用本项目 SAED 的调用适配。正常大解尘土还需要继续确认 4G 粒子层和落点／触发帧，不能直接复用超解 `gaxe_104` 宣称还原完成。66 是已确认的普通大解动作 `0x4B` 帧，尚未证明就是每个尘土层的发射帧。

资源部署可以用转换后的新资源加 NRO 触发。若要求完全单 NRO，则要把转换后的 EFL 和全部依赖字节嵌入 NRO，并接入 GU 资源注册／加载；这仍然需要转换资源格式。现有 Presentation 的 `0x258/0x259` 盾牌闪电不包含上述怪物命中点或地面尘土逻辑。

P-05（已实现，E-12、E-13 → F-06）：加载 NRO → 四处后摇链改 `0x7DC` → `main+002EA864` 跳到 NRO → 匹配盾斧／链／序号 0 时返回 0，否则调用原查询 → 补回比较 → 返回 `002EA86C` → 原循环保留其余派生。
