# Moveset 内置 4G 风格

2026-10-22：现行实现已合并到 `Moveset-to-4G/src/style/`，不再独立构建或安装Style NRO。菜单选择保存到 `cb_moveset_to_4g.ini` 的 `[style] selected`。4G配置编号为6，运行仍复用公会资源。

`0xAA/0xAB` 始终注册且可由所有盾斧调用；`0x44/0x4B` 是否转用它们只看 `[styles] yellow_shield_aed`。六项均按0..7配置：黄盾变正常AED默认武士道3和4G6，GP后退/防性默认6，后三项none；J防接黄盾独立默认开启，SAED保持全局。菜单确认/比较继续使用现场原表值，配置列表只保留八个编号。

当前配置见 [配置说明](Configuration.md)，实现来源见 [合并报告](2026-10-22_Moveset风格合并与编号配置.md)。下面保留首次独立Style实现时的原理与验证记录，产物大小、旧INI和旧开关说明属于历史版本。

2026-10-22。适用 MHGU v1.4.0，产物 `dist/cb_style_to_4g.nro`。本项目新增原版菜单入口和两套独立前置动作；现有音效、特效、攻击数据、超解瓶爆、防性仍由 Presentation／Moveset 负责。已完成构建、原版字节核对与离线执行验证，尚未运行完整游戏菜单或战斗测试。

## 使用与选择保存

使用盾斧，在原版狩猎风格菜单选择第七项 **4G**。菜单当前高亮、当前名称和说明也显示 4G；原六项仍可选择。仅本机玩家、公会底座、武器编号 14 且选择 4G 时重定向新动作。

菜单选择自动保存到当前用户存档根目录 `cb_style_to_4g.ini`，即时生效：

```ini
[plugin]
enabled = true

[style]
selected = false
```

选择 4G 时 `selected=true`；盾斧选择原六项时为 false。非盾斧的风格选择保留这份盾斧偏好。插件总开关通过 Forge → Plugin UI → CB 4G Style 保存，重启应用。

内部装备风格仍为公会 0。4G 偏好存在独立 INI，不写入装备套装，因此切换套装仍沿用该偏好；如果新套装不是公会盾斧，则不会接管动作。公会的两格狩技、资源和其它未改动作继续由游戏提供。

若要让原公会恢复原黄盾后续，将 Moveset 的 `yellow_shield_aed` 关闭。Style 不依赖该全局补丁，关闭后 4G 新动作仍接正常大解／超解；其它 Moveset 开关继续按各自原范围生效。

## 两套新动作

| 原公会前置 | 4G 新动作 | NRO 逻辑 variant | 原动画／表现使用的 variant |
|---|---|---|---|
| `0x44` | `0xAA` | 16 | 2 |
| `0x4B` | `0xAB` | 17 | 4 |

原盾斧分发只有 `0..0xA9`。新增桥接在 `main+0x011D5C64` 接入 AA／AB，其余动作完整重放原边界检查。新编号由 NRO 自己处理，不扩写原跳表或占用 main 的代码洞。

动作提交链 `Hit_func → 002AAEAC → 002AB654 → 002AB670 → 011D5AE8 → 00283090` 没有在写入 `player+0x250A` 前限制 A9；已知 A9 边界在上述盾斧分发器。另限定检查 `011D0000..011E1000` 中 17 处当前／前动作分类，原 44／4B 与新 AA／AB 在清理、命中分类、相机参数等外围逻辑中走相同路径，没有发现需要追加的兼容分支。

不能把 16／17 直接传入原前置函数：原动画表只有 16 项，而且原 variant2／4 的结束分支仍会进入黄盾 `0x4E/0x4F`。本项目在普通阶段用资源 variant2／4 调用原 `main+0x011DA204`，保留原动画、有瓶缓存和 Presentation 钩子；进入 actionState3 后传资源 variant0，由原函数按正常大解／超解逻辑提交后续。

原前置对 variant2／4 不建普通大解派生链，因此在阶段转换后补齐：

| 转换 | 白盾有瓶 | 白盾无瓶 | 强化盾有瓶 | 强化盾无瓶 |
|---|---|---|---|---|
| `0 → 2` | `0x7EC` | `0x7ED` | `0x7F0` | `0x7F1` |
| `2 → 3` | `0x7EE` | `0x7EF` | `0x7F2` | `0x7F3` |

调用原 `main+0x002E9C50(player,chain,0,resume)`；第一次 resume=0，续链 resume=1 保留缓存输入。旧 Moveset 已建立同一链时不重复初始化。

结束时由原函数提交的后续为：

| 盾状态 | 有瓶 | 无瓶 | 原动作参数 |
|---|---|---|---|
| 未强化 | `0x2E` 普通大解，variant1 | `0x2D` 普通大解，variant0 | `0x100C` |
| 强化盾 | `0x3B` 超解，variant2 | `0x3C` 超解，variant3 | `0x900C` |

这些目标、参数及派生链均与当前 Moveset 黄盾修复版的原指令执行结果核对。原动画表、动作资源和原公会动作 ID 不改。

## 输入重定向

`main+0x002ECEFC` 是原输入检查入口，唯一调用者为 Hit_func。先运行原检查，再仅将当前栈上 32 字节临时命令中的 `act_st=0x10`、`act_no=0x44/0x4B` 重定向为 AA／AB。

输入条件、cmd_param、Pre／Start／End、共享资源均保留。不能限定原检查返回 1 才重定向：输入可能已在先前帧缓存，后续返回 0 时仍提交命令。本入口不占用旧 Moveset 的 `main+0x002EA87C`。

## 原版第七行菜单

原菜单构造函数 `main+0x006376BC` 已按八行分配列表，节点为 `7,8,9,A,46,47,4E,4F`。原风格页只展示六行，本项目在盾斧风格页展示七行，并将节点 `0x4E` 的文本写为 4G；其它武器、狩技页面维持原流程。

第七项不能直接读取原六项表 `main+0x0162C5A0 = [0,1,2,3,5,4]`。两处桥接分别处理确认与当前项比较：

| main 偏移 | 原两条指令 | 新处理 |
|---|---|---|
| `0x0054924C` | `E7D17100 / E30103C4` | 行 6 返回公会 0，保存额外 4G 选择 |
| `0x00549784` | `E7927101 / E5901000` | 用仅供比较的 token 区分公会／4G，原表不读取行 6 |
| `0x011D5C64` | `E35000A9 / 8A00030B` | 新增动作 AA／AB，其余原分发不变 |

名称、当前高亮、状态切换和说明的入口钩子为 `00637958 / 00637B28 / 00638C20 / 00638D00 / 00638D34 / 006394B8`。行 6 的说明完全由新代码处理，避免原六项名称／说明查表越界。

菜单比较／确认桥接保留 NZCV、VFP 和现场寄存器，调用配置保存前保持八字节栈对齐。没有修改全游戏风格 getter，也没有把装备风格字节写成 6。

## 架构与验证

`menu.rs`、`actions.rs`、`selection.rs` 分别负责菜单、动作、选择归属；原玩家／装备字段通过 `game-api` 对象访问。配置、菜单存储和补丁事务复用共用模块，避免复制原前置函数或另写一套动画状态机。只在原菜单状态切换、输入检查或动作分发时工作，不增加全局每帧扫描。
